# Architecture

## Package layout

```
android_tv_guru/
  callsigns.py   Syntactic U.S. call-sign extraction from a channel name.
                 No external data — a pure regex over FCC naming conventions.
                 Canonical: every other module and every CLI script imports
                 this rather than re-implementing call-sign parsing.
  stations.py    StationDirectory: loads data/us_tv_stations.json, call sign
                 -> city/state. Missing entries are normal (partial
                 coverage); callers fall back to the original channel name
                 rather than guess. Also owns the station importers
                 (fetch_station_records_from_rabbitears, the primary
                 source; fetch_station_records_from_wikidata, a
                 supplementary fallback; build_station_directory merges
                 both) — see docs/DATA_SOURCES.md for the source decision.
  grouping.py    group-title classification: local network (requires a call
                 sign), IPTV-org category, Spanish/African & Caribbean
                 heuristics, "Other International - <cc>" fallback.
  epg.py         Production EPG pipeline: matches published channels against
                 legal EPG sources (tvguide.com, i.mjh.nz), writes reports +
                 the grabber input file, and merges grabbed XMLTV fragments
                 into AndroidTVGuru.xml/.xml.gz. See docs/EPG_MATCHING.md.
  playlists.py   Orchestration: fetch channels/streams/cities/subdivisions,
                 build Entry objects, write the master + category playlists,
                 write state playlists. Does NOT run EPG matching — that is
                 a separate pipeline/workflow step (see below).

scripts/                          Thin CLI wrappers around android_tv_guru.
  update_station_data.py            -> android_tv_guru.stations.build_station_directory()
  build_epg_source.py               -> android_tv_guru.epg.build_and_write()
  merge_epg.py                      -> android_tv_guru.epg.merge_guides() / write_guide_outputs()
None of these scripts re-implement call-sign extraction, station lookup, or
EPG matching logic — that would mean maintaining it twice. If you need new
matching/classification behavior, add it to the package, not a script.

data/
  us_tv_stations.json      Station directory (see docs/DATA_SOURCES.md).
  epg-overrides.json       Manual, human-reviewed EPG id overrides (empty by default).

epg/
  grabber-input.channels.xml   Generated by android_tv_guru.epg.build_and_write();
                                the input to iptv-org/epg's `grab` command.

reports/        Generated CSVs: epg-matches.csv, epg-unmatched.csv,
                epg-conflicts.csv, epg-coverage.csv.
docs/           This file, DATA_SOURCES.md, EPG_MATCHING.md.
tests/          pytest suite; tests/fixtures/data holds small, hand-written
                fixture channels/streams/stations so tests run offline.

build_android_tv_guru_m3u-1.py   Thin compatibility entry point; calls
                                  android_tv_guru.playlists.main(). Kept so
                                  the GitHub Actions workflow and any existing
                                  bookmarks keep working unchanged.
```

## Two independent pipelines, two workflows

Playlist generation and EPG generation are deliberately separate:

```
.github/workflows/update-playlist.yml   (daily / manual)
  build_android_tv_guru_m3u-1.py -> android_tv_guru.playlists.main()
    channels.json + streams.json + cities.json + subdivisions.json
      ├── grouping.determine_group()   (group-title)
      ├── callsigns.extract_callsign() (call sign, US only)
      └── stations.StationDirectory    (confident city/state, else fall back
                                         to the original channel name)
    ──▶ AndroidTVGuru.m3u, playlists/*.m3u, playlists/US_Locals_All.m3u,
        playlists/states/<State>.m3u

.github/workflows/update-epg.yml   (triggered after the above completes)
  scripts/update_station_data.py -> data/us_tv_stations.json (RabbitEars + Wikidata refresh)
  scripts/build_epg_source.py    -> android_tv_guru.epg.build_and_write()
      fetches tvguide.com + i.mjh.nz channel lists, matches against the
      channel ids published in AndroidTVGuru.m3u
    ──▶ epg/grabber-input.channels.xml, reports/epg-*.csv
  iptv-org/epg `grab` (pinned commit — see docs/EPG_MATCHING.md)
    ──▶ raw per-source XMLTV
  scripts/merge_epg.py -> android_tv_guru.epg.merge_guides() / write_guide_outputs()
    ──▶ AndroidTVGuru.xml, AndroidTVGuru.xml.gz
```

Both playlist and EPG generation publish to the same repo, but neither
workflow modifies files the other owns: `update-playlist.yml` never touches
`AndroidTVGuru.xml(.gz)` or `reports/`, and `update-epg.yml` never touches
`AndroidTVGuru.m3u` or `playlists/`.

## Design decisions worth knowing about

- **The call-sign gate is the primary conservative-classification mechanism.**
  A channel only lands in `US Local - <Network>` if its *name* is
  syntactically a real broadcast call sign (`android_tv_guru.callsigns`).
  National feeds like "ABC News Live" or "CBS Sports Network" don't look like
  call signs, so they're excluded by construction — the explicit
  `NATIONAL_FEED_DENYLIST` in `grouping.py` is a secondary, independently
  testable safety net, not the primary mechanism.
- **Display-name enrichment ("CALLSIGN — City, ST") never gates
  classification.** A channel can be `US Local - ABC` without a confident
  station match (it just keeps its original name); state playlists are the
  only outputs restricted to confidently matched stations, because sorting
  by state requires knowing the state.
- **The EPG header (`EPG_HEADER` in `android_tv_guru/playlists.py`) is a
  fixed constant, not derived from any live/external lookup**, specifically
  so a stale or dead upstream URL can never silently reappear after a
  playlist rebuild. See `docs/DATA_SOURCES.md` for why the previous
  IPTV-org-hosted guide URL was retired.
- **EPG matching never gates playlist classification or contents**, and
  playlist generation never blocks on EPG generation succeeding — they are
  independently rerunnable pipelines.
- **No live stream-health probing.** Tests use small, hand-written JSON
  fixtures instead of hitting real stream/guide URLs.
